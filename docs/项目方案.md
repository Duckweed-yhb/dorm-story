# 项目方案

> 把宿舍管理做成一个轻 RPG —— 与AI共生的宿舍经营小程序
> 2026 微信小程序开发大赛 · 参赛项目《宿舍物语》
> 文档生成日期：2026年9月22日

## 一、项目背景与赛事契合度

2026微信小程序开发大赛以"与AI共生"为主题，鼓励开发者利用AI能力创造优质小程序，并接入微信AI生态。大赛面向产品实用性（30%）、产品创新性（30%）、用户体验（20%）、作品完整度（20%）四个维度评审。

《宿舍物语》正是围绕这四个维度设计：以真实的宿舍管理痛点（值日混乱、物品短缺、沟通不畅）为切入点，用游戏化机制和AI能力提升用户粘性与体验，同时保证功能可落地、可上线、可持续运营。

## 二、产品定位

不是一个简单的"宿舍管理员工具"，而是让整个宿舍成为一个可以共同经营、升级、完成任务的"游戏单位"。产品把枯燥的日常琐事（扫地、打卡、公告）转译为游戏语言（副本、经验值、等级、属性），核心心智从"今天我要不要扫地"变成"我们宿舍今天能不能完成副本"。

### 2.1 目标用户

- 在校大学生 / 研究生宿舍成员（3–6人合住场景）
- 重视宿舍氛围与效率、有一定游戏化偏好的年轻用户
- 宿舍长 / 寝室管理者，需要低成本的协作与提醒工具

### 2.2 核心价值主张

| 痛点 | 传统方式的问题 | 宿舍物语的解法 |
| --- | --- | --- |
| 值日安排不公平、常忘记 | 口头约定，靠自觉，纠纷多 | AI自动排班 + 提醒 + 历史公平性分析 |
| 公共物品经常缺货 | 发现即缺，事后补救 | 物品台账 + 低库存提醒 + 任务化补货 |
| 宿舍氛围松散、缺乏认同感 | 无量化反馈，努力被忽视 | 宿舍等级、属性、经验值可视化成长 |
| 沟通靠微信群，信息易淹没 | 公告刷屏、日历各用各的 | 统一公告 + 共享日历 + 打卡看板 |

## 三、基础功能模块

产品以微信小程序技术体系为基础自主开发，覆盖以下九大基础功能：

- 自动安排值日
- 值日提醒
- 宿舍任务
- 宿舍费用（AA / 分摊记录）
- 公共物品（台账与补货）
- 公告
- 共享日历
- 宿舍成员（档案与角色）
- 共同打卡

## 四、游戏化系统设计

### 4.1 宿舍属性

每个宿舍拥有五维属性（卫生、团结、活跃、秩序、自律），以1–5星展示，随真实行为数据动态变化，并对应一个宿舍总等级（如 Lv.8）。属性来自打卡率、任务完成率、物品补给及时率、互动频次等可统计行为的加权计算。

### 4.2 经验值体系（示例）

| 行为 | 获得经验值 |
| --- | --- |
| 完成值日 | +10 XP |
| 补充公共物品 | +15 XP |
| 全员打卡 | +30 XP |
| 宿舍活动 | +50 XP |
| 连续 7 天完成任务 | +100 XP |

经验值累积驱动宿舍等级成长，等级解锁称号、皮肤、专属公告样式等轻量激励，形成"真实行为 → 可见成长"的正反馈闭环。

## 五、AI能力接入

产品鼓励接入微信AI生态，AI不是装饰性功能，而是承担排班、分析、生成三类核心工作：

- 自动生成值日安排：结合成员空闲时间、历史完成情况生成排班表
- 根据历史情况调整任务：识别频繁拖延或不公平的任务分配并自动纠偏
- 分析宿舍活跃度：识别活跃/沉默成员，辅助宿舍长关注冷门问题
- 发现长期没人完成的任务：主动预警，避免任务被遗忘
- 自动生成宿舍事件 / 根据成员行为生成挑战：如"本周无人补充纸巾"触发一个趣味小任务
- 生成每周宿舍总结：把打卡、任务、属性变化自动汇总成一段可读的"周报文案"

所有AI使用过程需合规可追溯，遵循大赛"严禁AI生成抄袭作品、违规套用现成源码"的要求，核心创意与实现由团队原创完成，AI仅作为功能能力被调用。

## 六、评审维度对照自查

| 评审维度 | 占比 | 本项目对应设计 |
| --- | --- | --- |
| 产品实用性 | 30% | 覆盖真实宿舍管理场景九大基础功能，可直接替代群聊+表格的粗放管理方式 |
| 产品创新性 | 30% | 游戏化经营宿舍 + AI排班/分析/生成三重能力，同类产品稀缺，差异化明显 |
| 用户体验 | 20% | 属性可视化、经验值即时反馈、打卡与提醒轻量化，降低使用门槛 |
| 作品完整度 | 20% | 严格对照赛程排期开发，确保7月17日–10月17日窗口内正式上线并稳定运行 |

## 七、团队分工建议

- 产品 / 交互：负责功能优先级、游戏化数值设计、评审汇报材料
- 前端（小程序）：WXML/WXSS/JS 页面开发，打卡、任务、日历、公告等UI
- 后端 / 云开发：数据模型、云函数、定时任务、AI接口调用与结果落库
- AI集成：排班算法/AI Prompt设计、活跃度分析逻辑、周报文案生成

（若团队人数少于以上角色数，可由1–2人兼多角色，具体分工在《项目开发时间安排》中细化到人。）
