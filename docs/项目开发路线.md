# 项目开发路线

> 从技术架构到功能模块的实现路径规划
> 2026 微信小程序开发大赛 · 参赛项目《宿舍物语》
> 文档生成日期：2026年9月22日

## 一、技术架构总览

| 层级 | 技术选型 | 说明 |
| --- | --- | --- |
| 前端 | 微信小程序原生开发（WXML/WXSS/JS），或 uni-app（可选） | 遵循《微信小程序设计指南》，保证在微信内原生流畅运行 |
| 后端 | 微信云开发（云函数 + 云数据库 + 云存储） | 免运维、与小程序无缝集成，适合短周期开发 |
| AI能力 | 云函数内调用AI接口（结构化Prompt + JSON输出） | 覆盖排班生成、行为分析、文案/事件生成三类场景 |
| 定时任务 | 云开发定时触发器 | 驱动每日提醒、每周总结、低库存检测 |

## 二、数据模型设计（核心集合）

| 集合（collection） | 关键字段 | 用途 |
| --- | --- | --- |
| dorm（宿舍） | dormId, level, exp, attrs{卫生/团结/活跃/秩序/自律} | 宿舍基本信息与游戏化状态 |
| member（成员） | memberId, dormId, name, role, openid | 宿舍成员档案与身份 |
| duty（值日） | dutyId, dormId, date, memberId, status | 值日排班与完成状态 |
| task（任务） | taskId, dormId, type, assignee, deadline, status | 宿舍任务/挑战/物品补给任务 |
| checkin（打卡） | checkinId, dormId, memberId, date | 共同打卡记录 |
| item（公共物品） | itemId, dormId, name, stock, threshold | 物品台账与低库存预警 |
| announcement（公告） | annId, dormId, content, createdAt | 宿舍公告 |
| expense（费用） | expId, dormId, amount, payer, splitTo[] | 宿舍费用分摊记录 |
| aiLog（AI调用日志） | logId, dormId, type, prompt, result, createdAt | AI使用过程留痕，满足合规可追溯要求 |

## 三、功能模块与实现路径

### 3.1 基础协作模块

- 宿舍成员：创建宿舍 → 邀请码/二维码加入 → 成员角色设置（宿舍长/成员）
- 共享日历：日历UI组件 + 事件（值日/活动/截止日）聚合展示
- 公告：宿舍长发布 → 全员小程序订阅消息提醒
- 宿舍费用：录入支出 → 自动均摊/自定义分摊 → 成员间欠款一览

### 3.2 值日与任务模块

- 值日排班：先实现规则版排班（轮转算法）→ 接入AI优化版（结合请假、历史完成率动态调整）
- 值日提醒：云开发定时触发器 + 小程序订阅消息，在值日当天推送提醒
- 宿舍任务：支持手动创建任务与AI自动生成的"挑战型任务"两类来源
- 公共物品：物品库存台账，低于阈值自动生成"补货任务"并推送提醒

### 3.3 游戏化系统模块

- 经验值引擎：统一的云函数 addExp(dormId, action)，各业务模块完成后调用，避免多处重复计算逻辑
- 属性计算：云函数定时任务按周期（如每日）重新计算五维属性星级，写回 dorm 集合
- 等级与成长可视化：前端组件展示等级、经验条、属性雷达图/星级
- 共同打卡：每日打卡入口 + 全员打卡触发额外经验值奖励逻辑

### 3.4 AI能力模块

- 自动生成值日安排：云函数拼装成员空闲时间与历史数据 Prompt，调用AI返回结构化排班JSON
- 任务动态调整：分析 duty/task 完成率，识别长期拖延项并触发AI建议调整
- 活跃度分析：基于打卡、任务、公告互动频次生成活跃度评分与可视化
- 宿舍事件/挑战生成：结合成员行为数据（如"本周无人补货"）触发AI生成趣味挑战文案
- 每周总结生成：定时触发器在每周固定时间调用AI，汇总当周数据生成周报文案并推送

所有AI调用统一记录到 aiLog 集合，保证过程留痕、可追溯、可审计

## 四、开发路径（由内到外）

建议按以下顺序推进，确保任意阶段中止都有一个可运行、可展示的版本：

1. 打通骨架：账号体系 + 建宿舍/加入宿舍 + 基础导航
2. 跑通最小闭环：值日排班（规则版）+ 打卡 + 经验值引擎，让"完成行为 → 获得经验值 → 属性变化"闭环可见
3. 补齐协作模块：任务、公共物品、公告、共享日历、费用
4. 接入AI能力：从"自动生成值日安排"开始，逐步扩展到分析、事件生成、周报生成
5. 体验打磨与稳定性：空状态、加载态、异常兜底、订阅消息节奏优化
6. 上线与材料准备：正式发布 + 撰写作品介绍PDF + 报名材料提交

## 五、风险与兜底方案

| 风险点 | 兜底方案 |
| --- | --- |
| AI接口响应慢或不稳定 | 所有AI功能均保留"规则版"兜底逻辑，AI仅作为增强而非唯一实现路径 |
| 开发周期短，功能可能无法全部完成 | 严格按第四章①-③优先完成，④-⑥为增强项，可视进度取舍，保证核心闭环优先可用 |
| 多人协作代码冲突 | 使用 Git 分支管理，按模块拆分文件，云函数按功能独立部署 |
| 审核/上线不通过 | 预留至少2天缓冲期用于审核问题整改，避免压线提交 |
