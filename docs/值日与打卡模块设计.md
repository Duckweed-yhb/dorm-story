## 一、数据模型（集合设计）

### 1. `duty`（值日）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `dutyId` | string | 主键，自增/随机生成 |
| `dormId` | string | 所属宿舍（关联 `dorm`） |
| `date` | string | 值日日期，`YYYY-MM-DD` |
| `memberId` | string | 当值成员（关联 `member`） |
| `status` | string | `todo`（待完成）/ `done`（已完成） |
| `source` | string | `rule`（规则版）/ `ai`（AI 版，阶段3用） |
| `remark` | string | 备注（可选） |
| `createdAt` | date | 创建时间 |
| `updatedAt` | date | 更新时间 |

**索引建议**：`dormId + date` 联合索引（查某宿舍某周/某天排班）；`dormId + memberId`（统计公平性）。

### 2. `checkin`（打卡）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `checkinId` | string | 主键 |
| `dormId` | string | 所属宿舍 |
| `memberId` | string | 打卡成员 |
| `date` | string | 打卡日期 `YYYY-MM-DD` |
| `createdAt` | date | 打卡时间 |

**唯一约束/索引**：`dormId + memberId + date` 唯一，防止重复打卡。

### 3. 宿舍排班游标（可挂在 `dorm` 集合上）

| 字段 | 说明 |
| --- | --- |
| `dorm.lastAssignIndex` | 上次排班轮到的成员序号，保证公平轮转 |

## 二、规则版排班算法（先最小，够用）

**目标**：给定宿舍成员名单 + 日期范围，生成一周值日安排，公平无冲突。

**伪代码**：
```
scheduleDuty(dormId, startDate, endDate):
    members = getMembers(dormId)          # 按加入顺序
    if members 为空: return 错误("宿舍暂无成员")
    start = dorm.lastAssignIndex or 0
    days = [startDate .. endDate]          # 每天 1 人
    for i, date in days:
        memberIdx = (start + i) % len(members)
        dutyId = genId()
        写 duty { dutyId, dormId, date, memberId: members[memberIdx], status:'todo', source:'rule' }
    dorm.lastAssignIndex = (start + len(days)) % len(members)   # 下次接着排
    return 生成的排班列表
```

**本期边界**（先不做）：请假/调休、多人同日、跨宿舍——留到阶段3 AI 版；异常入参（无成员、日期非法）返回可读错误，不崩。

## 三、云函数接口契约（乙对外提供）

| 云函数 | 入参 | 返回 | 说明 |
| --- | --- | --- | --- |
| `scheduleDuty` | `{ dormId, startDate, endDate }` | `{ dutyList }` | 生成/覆盖某周排班 |
| `getDuty` | `{ dormId, date? }` | `{ dutyList }` | 查某天或整周排班 |
| `completeDuty` | `{ dutyId, memberId }` | `{ status }` | 完成值日 → 调丙 `addExp` |
| `doCheckin` | `{ dormId, memberId }` | `{ checkinId, expAdded }` | 打卡 → 全员则加额外经验 |
| `getCheckin` | `{ dormId, date }` | `{ members, checked[] }` | 当天打卡情况 |

## 四、与丙 `addExp` 的对接（action 枚举约定）

> 经验值统一由丙的云函数 `addExp(dormId, action)` 计算，乙只负责**在正确时机调用**，不自己算 XP。

| 触发时机 | action | 经验值（丙定） |
| --- | --- | --- |
| 完成一次值日 | `value_duty` | +10 |
| 全员打卡（当天全成员完成） | `full_checkin` | +30 |

调用示例：`completeDuty` 内完成写库后 → `call addExp({ dormId, action: 'value_duty' })`；`doCheckin` 内判定当天全员已打卡 → `call addExp({ dormId, action: 'full_checkin' })`。

> 与丙对齐动作：确认 action 命名一致（可用 `value_duty` / `full_checkin`），若丙另有命名，以丙的清单为准。
